# Amigurumi 아키텍처

캐릭터 이미지 → 아미구루미 도안 생성 시스템의 구조를 정의합니다.
설계 근거는 [research.md](./research.md), 최종 출력 형식은 [spec/output-spec.md](../spec/output-spec.md)를 참고하세요.

---

## 1. 설계 원칙

| # | 원칙 | 이유 |
| --- | --- | --- |
| P1 | **신경망은 "보는 일"만, 코 수는 알고리즘이 계산** | VLM이 실행 가능한 도안을 직접 만드는 비율은 매우 낮고, 파인튜닝해도 실행 정확도가 오르지 않았다 (CrochetBench) |
| P2 | **3D 형태를 거쳐서 도안을 만든다** | 3D 형태 → 도안은 결정론적으로 풀 수 있음이 입증됐다 (AmiGo, Knitty, Stitch Meshes) |
| P3 | **파츠 단위로 생각한다** | 캐릭터 아미구루미는 머리·몸통·귀·팔을 따로 떠서 꿰맨다. 파츠 하나는 대부분 축을 따라 도는 회전체에 가깝다 |
| P4 | **검증을 통과한 도안만 출력한다** | 코 수가 틀린 도안은 뜰 수 없다. 사람이 검산해야 한다면 모델의 의미가 없다 |
| P5 | **시뮬레이션해서 입력과 비교한다** | 코 수가 맞아도 모양이 틀릴 수 있다. 렌더 비교는 CrochetBench가 쓴 평가 방식이다 |
| P6 | **사람이 중간에 확인·수정할 수 있다** | 사진 한 장으로는 뒷면·깊이·실제 크기를 알 수 없다 (CrochetPhoto2Pattern도 같은 결론) |
| P7 | **모듈은 교체할 수 있게** | 이미지→3D 모델은 빠르게 바뀐다. 중간 데이터 형식만 고정하고 모델은 바꿔 끼운다 |

```

        ▼
 ╔═══════════════════════════ 인식 단계 (신경망) ══════════════════════════╗

 ║      ▼                                                                   ║
 ║   ② Part Graph (중간 표현, JSON)                                         ║
 ║      ▼                                                                   ║
 ║ M5 도안 합성     프로파일 → 단별 코 수 → 늘림/줄임 배치 → 조립 위치     ║

 ║ Markdown / PDF       ║     ║ 도안 → 3D → 렌더 → 입력과 비교      ║
 ║ 한국어 / 영어        ║     ║ CrochetPARADE DSL 내보내기          ║

```

데이터 형식은 세 개로 고정합니다. 모듈 사이에서는 이 형식으로만 데이터를 주고받습니다.

| 형식 | 만드는 곳 | 쓰는 곳 | 형태 |
| --- | --- | --- | --- |
| ① Part Mesh Set | M3 | M4 | 파츠별 메시(GLB) + 파츠 이름 + 텍스처 |
| ② **Part Graph** | M4 | M5, M7 | JSON. 파츠별 프로파일·색·부착 관계 (§4) |
| ③ **Pattern JSON** | M5 | M6, M7, M8 | JSON. [spec/pattern.schema.json](../spec/pattern.schema.json) |

②가 있어서 **신경망 쪽(M1~M3)과 알고리즘 쪽(M5~M8)을 따로 개발**할 수 있습니다.
v0.1에서는 Part Graph를 손으로 써서 넣고, 알고리즘 쪽을 먼저 완성합니다.

## 3. 인식 단계 (M1~M3)

### M1 전처리
- 배경 제거, 캐릭터 영역 자르기, 정사각형으로 맞추기
- TRELLIS.2 같은 모델은 자체 전처리를 포함하므로 해당 모델의 방식을 따른다.

### M2 3D 복원

| 후보 | 용도 | 라이선스 | 사양 |
| --- | --- | --- | --- |
| **TRELLIS.2** | 기본 (품질) | MIT | GPU 24GB 이상 |
| **TripoSR** | 개발·시험용 (속도, 저사양) | MIT | 가벼움 |
| ~~Hunyuan3D 2.1~~ | **사용 불가** | 한국은 라이선스 지역에서 제외 | |

- 출력: 텍스처가 입혀진 메시 1개 (GLB)
- 향후: 정면·옆면·뒷면 이미지를 여러 장 넣는 옵션 (뒷면을 지어내는 문제 완화)

### M3 파츠 분해

두 가지 경로를 실험해서 고릅니다.

| 경로 | 방식 | 장점 | 단점 |
| --- | --- | --- | --- |
| A | M2 결과 메시 → **PartField**로 분할 | M2 모델을 자유롭게 교체 가능 | 분할 경계가 아미구루미 파츠와 다를 수 있음 |
| B | 이미지 → **PartCrafter**로 파츠별 메시를 바로 생성 | 가려진 파츠까지 생성. 파츠가 처음부터 닫힌 메시 | 모델 하나에 종속 |

- **파츠 이름 붙이기:** VLM에게 파츠 렌더 이미지를 보여주고 정해진 목록(`head`, `body`, `ear`, `arm`, `leg`, `tail`, `muzzle`, `accessory` …) 중에서 고르게 한다. **자유 텍스트나 숫자는 받지 않는다.**
- **사용자 확인:** 파츠를 합치기·나누기·이름 수정하기. 잘못된 분해는 이후 모든 단계를 망치므로 여기서 바로잡는다.

## 4. 중간 표현: Part Graph

아미구루미 파츠 하나는 **축을 따라 단을 쌓은 것**이고, 한 단의 코 수는 **그 높이에서의 둘레**로 정해집니다.
그래서 파츠를 아래처럼 단순화합니다.

```
          축(axis) 방향 →
   s=0                                s=L
    ●━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━●     s: 축을 따라 잰 거리
    │   ╭──────╮                        │
    │ ╭─╯      ╰──╮        단면 둘레 P(s)를  │
    │╭╯           ╰──╮     일정 간격으로 측정  │
    ││               ╰─╮                   │
    │╰╮              ╭─╯                   │
    │ ╰─╮      ╭─────╯                     │
    │   ╰──────╯                           │
```

```jsonc
{
  "schema_version": "0.1",
  "target_height_cm": 10,
  "gauge": { "stitch_width_mm": 5.0, "round_height_mm": 4.5 },  // 실 굵기·바늘 호수로 결정 (§5.1)
  "parts": [
    {
      "id": "head",
      "label": "head",                       // M3에서 고른 이름
      "axis": {                              // 파츠의 중심축 (월드 좌표, 단위 mm)
        "origin": [0, 0, 62], "direction": [0, 0, 1], "length_mm": 48
      },
      "profile": [                           // 축을 따라 측정한 단면
        { "s_mm": 0,  "perimeter_mm": 0,   "aspect": 1.0 },
        { "s_mm": 6,  "perimeter_mm": 70,  "aspect": 1.0 },
        { "s_mm": 24, "perimeter_mm": 150, "aspect": 1.1 },   // aspect: 단면 장축/단축 비
        { "s_mm": 48, "perimeter_mm": 0,   "aspect": 1.0 }
      ],
      "end_open": false,                     // 끝이 열려 있으면(꿰매 붙이는 쪽) true
      "flat": false,                         // 얇아서 솜 없이 눌러 펴는 파츠
      "color_bands": [                       // 축 구간별 색 (단 경계에서만 색 변경)
        { "s_from_mm": 0, "s_to_mm": 48, "hex": "#F6D33C" }
      ],
      "features": [                          // 눈·입 등 (표면 위치)
        { "type": "eye", "s_mm": 26, "angle_deg": -20, "size_mm": 8 },
        { "type": "eye", "s_mm": 26, "angle_deg": 20,  "size_mm": 8 }
      ]
    }
  ],
  "attachments": [
    { "part": "ear", "target": "head", "s_mm": 40, "angle_deg": 50, "tilt_deg": 15 }
  ],
  "symmetry": [ ["ear_l", "ear_r"] ]         // 좌우 대칭 파츠 → 도안에서 quantity 2로 묶음
}
```

**왜 반지름이 아니라 둘레인가:** 코 수는 그 단의 둘레 ÷ 코 너비로 정해집니다. 단면이 타원이거나 울퉁불퉁해도 **둘레만 맞으면 코 수가 맞습니다.** 솜을 넣으면 단면은 어차피 둥글어집니다.

**M4 알고리즘 (파츠 메시 → Part Graph)**
1. **축 찾기:** 파츠 메시의 주성분 분석(PCA)으로 가장 긴 방향을 축으로 정한다. 휘어진 파츠(꼬리 등)는 v0.x에서 직선 축으로 근사한다.
2. **시작점 정하기:** 축의 두 끝 중 **닫힌 쪽**(다른 파츠와 붙지 않는 쪽)에서 시작한다. 매직링이 그쪽에 온다.
3. **단면 측정:** 축에 수직인 평면으로 메시를 잘라(trimesh 단면) 둘레와 장단축 비를 잰다.
4. **얇은 파츠 판정:** 두께/너비 비가 기준 이하이면 `flat: true`로 바꾼다. 둘레는 너비의 2배로 둔다.
5. **색:** 텍스처에서 구간별 대표색을 뽑는다. CIELAB 공간에서 k-means로 군집화하고, 가까운 구간끼리 합친다.
6. **부착:** 다른 파츠와 닿는 영역의 중심을 대상 파츠 좌표 `(s, angle)`로 바꾼다.
7. **크기 맞추기:** 전체 높이가 `target_height_cm`가 되도록 모든 길이를 같은 비율로 늘이거나 줄인다.

## 5. 설계 단계 (M5~M6)

### 5.1 게이지 모델

| 입력 | 결정되는 값 |
| --- | --- |
| 실 굵기 (CYC 0~7), 바늘 호수 | 짧은뜨기 1코의 너비 `w`와 1단 높이 `h` (mm) |

- 초기값은 경험치 표로 시작하고, **실물을 떠서 측정한 값으로 보정**한다 (v0.5).
- 아미구루미는 일반 뜨개보다 바늘을 한 치수 작게 써서 촘촘하게 뜬다. 이 점을 표에 반영한다.

### 5.2 M5 도안 합성 (Part Graph → Pattern JSON)

파츠마다 다음 순서로 계산합니다.

1. **단 나누기:** 프로파일 곡선의 **표면 길이**를 따라 `h` 간격으로 점을 찍는다. 점 하나가 단 하나다.
   - 축 길이가 아니라 표면 길이를 쓰는 이유: 공의 아래쪽처럼 둘레가 빠르게 변하는 구간은 축으로는 짧아도 실제로는 여러 단을 떠야 한다.
2. **목표 코 수:** `n_i = round(P(s_i) / w)`
3. **뜰 수 있게 제약 걸기**
   - 첫 단: 매직링 6코 (아주 작은 파츠는 4~5코)
   - 한 단에서 최대 2배까지 늘릴 수 있다: `n_i ≤ 2·n_{i-1}`
   - 한 단에서 최대 절반까지 줄일 수 있다: `n_i ≥ ⌈n_{i-1} / 2⌉`
   - 변화량이 너무 들쭉날쭉하지 않게 평활화한다.
   - 선택: 6의 배수로 맞추는 "6등분 성형". 모양이 깔끔하고 도안이 읽기 쉬워진다.
4. **늘림·줄임 배치:** 변화량 `d = n_i − n_{i-1}`을 한 단 안에 **고르게 나눈다.**
   - 예: 24 → 30 이면 `(sc 3, inc) ×6`
   - 단마다 시작 위치를 엇갈려서 육각형 모양을 막는다.
   - 나누어떨어지지 않으면 나머지를 고르게 흩어 놓는다. 이 경우 `repeat`을 쓰지 않고 풀어서 쓴다.
5. **같은 단 묶기:** 코 수가 같은 연속 단은 `R7–R12`처럼 범위로 묶는다.
6. **마무리:** 끝 둘레가 0에 가까우면 6코까지 줄여 `close`, 열려 있으면 `leave_tail`
7. **작업 넣기:** 색 구간 경계 → `color`, 눈 위치 → `insert_safety_eyes`, 닫기 전 → `stuff`
8. **조립:** `attachments`의 `(s, angle)`을 대상 파츠의 단 번호와 `anchor` / `offset_stitches`로 바꾼다.
9. **난이도 적용**

   | 난이도 | 규칙 |
   | --- | --- |
   | 초급 | sc·inc·dec만 사용, 아주 작은 파츠는 자수로 대체, 색 변경 최소화 |
   | 중급 | 반코뜨기·hdc 허용, 작은 파츠 유지 |
   | 고급 | 단 중간 색 변경, 파츠를 이어서 뜨기 등 |

### 5.3 M6 검증

- `spec/validate_pattern.py`의 V1~V8을 모두 통과해야 출력한다.
- M5는 결정론적이라서 **검증에 실패하면 M5의 버그**다. 다시 생성할 일이 아니라 고칠 일이다. 이 점이 LLM 생성 방식과 가장 다른 부분이다.

## 6. 시뮬레이션·평가 (M7)

### 6.1 자체 경량 시뮬레이터 (회전체)

M5를 거꾸로 계산합니다: Pattern JSON → 3D

1. 단마다 둘레 = `count × w` → 반지름 `r_i = count × w / 2π`
2. 이웃한 단 사이의 표면 거리를 `h`로 두고, 높이 증가량 = `√(h² − (r_i − r_{i−1})²)`
3. `stuffing`에 따라 단면을 부풀리거나(`firm`) 납작하게(`none`) 만든다.
4. `assembly` 위치에 파츠를 배치하고, `color`에 따라 색을 칠한다.
5. 정면·옆면을 렌더링한다.

### 6.2 평가 지표

| 지표 | 비교 대상 | 의미 |
| --- | --- | --- |
| 실루엣 IoU | 시뮬레이션 렌더 ↔ 입력 이미지의 마스크 | 전체 모양이 맞는가 |
| DINO 유사도 | 시뮬레이션 렌더 ↔ 입력 이미지 | 캐릭터처럼 보이는가 (CrochetBench 방식) |
| 프로파일 오차 | 시뮬레이션 둘레 ↔ Part Graph 둘레 | M5 변환이 형태를 얼마나 보존하는가 |
| 색차 ΔE2000 | 추천 실 색 ↔ 이미지 색 | 색이 맞는가 |
| 검증 통과율 | V1~V8 | 100%여야 함 |

### 6.3 외부 정밀 검증
- Pattern JSON → **CrochetPARADE DSL 내보내기**로 코 단위 시뮬레이션과 대조한다.
- CrochetPARADE는 GPLv3라서 코드를 포함하지 않고 형식만 맞춘다.

## 7. LLM / VLM의 역할 범위

| 허용 | 금지 |
| --- | --- |
| 파츠 이름 고르기 (정해진 목록 안에서) | 코 수·단 수 생성 |
| 난이도에 따라 어떤 디테일을 생략할지 제안 | 도안 텍스트 직접 작성 |

도안 본문은 항상 Pattern JSON에서 **템플릿으로 렌더링**합니다 (M8).

| 데이터 형식 | Pydantic v2 모델 + JSON Schema |
| 메시 처리 | trimesh (단면 측정), numpy, scipy |
| 색 | scikit-image (CIELAB, ΔE2000), scikit-learn (k-means) |
| 신경망 실행 | PyTorch, 각 모델의 공식 코드 |
| 렌더링 | pyrender 또는 Blender(헤드리스) |
| 도안 문서 | Jinja2 템플릿 → Markdown, PDF |
| 서비스 (v1.0) | FastAPI + 웹 3D 뷰어 (three.js) |

**실행 환경**
- M4~M8은 CPU만으로 동작한다. v0.1~v0.2는 노트북에서 개발할 수 있다.
- M2·M3는 GPU 24GB 이상이 필요하다 (TRELLIS.2 기준). 클라우드 GPU에서 따로 실행하고 결과(GLB)만 넘긴다.

## 11. 위험 요소와 대응

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 2D 일러스트에서 3D 복원 품질이 낮음 | 전체 품질 저하 | 여러 모델 비교(v0.3), 여러 장 입력 옵션, 사용자 수정 단계 |
| 파츠 분해가 아미구루미식 분할과 다름 | 도안 구조가 어색함 | 사용자 확인, 이름 목록 기반 후처리 규칙, 필요하면 합성 데이터로 파인튜닝 |
| 솜을 넣으면 형태가 바뀜 | 시뮬레이션과 실물이 다름 | 회전체 모델에 팽창 보정 계수를 두고, 실물 시험으로 보정 |
| 휘어진 파츠, 한쪽으로 쏠린 성형 | 회전체 근사로 표현 불가 | v0.x 범위 밖. 이후 AmiGo식 Crochet Graph로 확장 |
| 모델 라이선스 | 사용·배포 제한 | MIT 모델 우선. PartField·PartCrafter 라이선스는 도입 전 확인 |
| 저작권 있는 캐릭터 | 도안 배포 문제 | 개인 소장 용도 안내. 평가 세트는 자체 제작 캐릭터로 구성 |
